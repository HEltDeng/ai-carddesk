# 后台与账号功能（2026-10-26）

后台入口：https://ai.mychangliapp.cn/admin 。商城账号入口：https://ai.mychangliapp.cn/#account 。

## 后台

- 概览：订单量、商品数量、已付款单量、实收交易额、退款登记额、净收款、当前待付款、卡密兑换量。每笔订单当前对应一件商品。
- 日期使用北京时间，结束日期包含全天。订单量按下单时间统计，实收按付款回调时间统计，退款按退款结果登记时间统计。卡密面额不会被重复计入现金收入；退款登记不执行资金转账。
- 订单：搜索订单号、买家账号或充值邮箱；筛选状态和下单日期；显示下单、付款、完成时间。导出筛选结果（单次最多 5000 条），导出动作进入审计。继续保留原有批量暂停、关闭、结果登记及工单功能。
- 买家账号：分页搜索账号、绑定邮箱、验证状态、启停状态及登录时间。可停用账号或设置新密码。重置密码需再次验证管理员密码，会撤销全部会话、待用验证码与购买授权。买家原密码不可恢复或查看。
- 商品交付账号：进入已付款或已核销订单的“登记 / 查看”入口。账号与密码均加密保存；查看、更新都需管理员密码和操作原因；普通运营无权限。显示密码由操作者主动点击，查看区域 60 秒后自动清除。登记交付信息不会自动把订单标记为完成；核验履约结果后使用既有状态操作。买家只能在本人已完成订单中查看交付信息。
- 审计：按日期、操作、结果、操作者和对象搜索并分页；包括注册登录、邮箱验证、风控拦截、下单、支付确认、状态变化、后台修改、导出、交付密码查看。记录操作人、时间、来源摘要与结果，不保存密码、验证码或 Session 原文。

审计表禁止普通 UPDATE / DELETE，记录串联 HMAC，可使用“校验日志完整性”检查。旧审计记录在迁移时建立基线，不能证明迁移前的真实性。校验能力针对本地日志链；尚未建立独立外部存证，不能防止拥有数据库及密钥的服务器管理员整体重写日志，或截断尾部后替换备份。不要描述为绝对不可篡改。

## 买家与购买验证

1. 注册站内账号（3–40 位字母、数字、下划线或短横线；密码至少 12 位）。
2. 绑定邮箱，输入收到的验证码。绑定成功同时获得当前会话的一次购买授权。
3. 创建每一笔新订单前都需要一次邮箱验证授权。验证码和购买授权均 10 分钟有效；每个验证码最多尝试 5 次；验证码不可重复使用，也不可在其他浏览器会话使用。
4. 成功创建订单时，在同一数据库事务中消耗购买授权。重复提交同一请求仍返回同一订单，不多消耗验证码、不重复扣卡。
5. 每个买家最多 3 笔待付款、每小时最多 10 笔新支付订单；每个来源最多 8 笔待付款、每小时最多 30 笔新订单。更换 Cookie、退出重登不重置买家额度。未付款不占卡密库存，15 分钟到期自动关闭。付款通知迟到仍记录真实付款并要求更新过期充值凭证。
6. 买家重新登录后可查看本人订单、继续支付或补充账号，不依赖原浏览器 Cookie。原有历史访客订单继续支持订单号与查询码查询。
7. 忘记密码使用已验证邮箱接收验证码；重置后撤销全部登录会话。账号停用同样撤销全部会话和购买授权。

登录邮箱是本站买家的联系方式，充值账号邮箱是订单履约目标；二者分开记录，不强制相同。站内注册会话与管理员会话使用独立 HttpOnly Cookie，买家登录不会获得后台权限。

## 邮件配置

按用户要求，当前不接入真实发信邮箱，仅完成配置入口。

在“设置 → 邮箱验证码”填写 SMTP 服务器、用户名、邮箱授权码、发信地址及加密端口。支持 465/TLS、587/STARTTLS；SMTP 授权码加密保存，接口不回显，留空保持原值。只允许公开网络邮件服务器，验证 TLS 证书。

验证码每个邮箱每分钟最多 1 次、每小时最多 5 次；每个账号每小时最多 5 次；每个来源每小时最多 20 次，并有请求级频率限制。发送失败不产生可用验证码；错误与日志不输出邮件服务密码或验证码。

未配置 SMTP 时显示“邮箱验证服务暂不可用”，不允许跳过验证。配置后需用自有测试邮箱实际完成发送、收件和验证验收；当前自动化测试使用模拟邮件发送，没有发送真实邮件。不要在聊天中发送 SMTP 授权码，应在 HTTPS 后台填写。

## 部署与恢复

源代码沿用 FastAPI + SQLite + 独立 worker。部署前停止 Web 和 worker，将完整数据库与密钥备份到服务器 `/var/backups/ai-carddesk/pre-backend-<时间>/`，再执行增量迁移并切换 release。

日常备份保留账号、订单、加密交付信息及审计，清除短期充值凭证、浏览器会话、买家会话、验证码和购买授权；受保护的恢复密钥独立保存在备份目录。新快照用 SQLite 查询 `SELECT sha256 FROM carddesk_backup_key WHERE id=1` 读取密钥指纹，恢复时使用 `keys/<指纹>.key` 并核对其 SHA-256。早期快照使用备份根目录原有的 `encryption.key`。请将快照和对应恢复密钥一并纳入备份保管。备份仍在同一服务器，尚无异地备份。

`deploy/update.sh` 只更新已有部署，不修改 Nginx、DNS、服务账户权限或已有支付配置。依赖变化时，更新脚本先创建独立虚拟环境并校验依赖，切换时记录原解释器路径到升级快照目录的 `previous-runtime`。更新失败会尝试恢复旧源码和原虚拟环境并启动服务；不会自动回写数据库快照，以免覆盖升级后可能产生的交易。若恢复到不支持审计链的旧版本，其新增审计不能继续生成新链，恢复前需安排维护窗口并核对差异，或优先修复新版本。数据库恢复必须在维护窗口停止所有写入并核对快照后进行。

支付和真实履约仍未接入。本次不进行真实付款、退款或会员充值。
